# Handoff — `refactor/sync-cleanup`, the `apps/web` read seam

Written 2026-08-16. Branch head `22c3ff2`. Worktree
`F:\simmer-mosquito\.claude\worktrees\data-fetching-audit-web-admin-bb7333`.

This branch is a ground-up rewrite of the data-sync layer. No backwards
compatibility. TanStack DB is transport only, the server is where things are
truly validated, every mutation names a command, and the only per-table
definition is the schema. Clients declare `syncMode`, `gcTime` and `mutations`;
`packages/sync` holds no opinion on any of them.

The server half is done and committed. `apps/web` is mid-migration: the
collections all exist, one surface is through the new read seam, and fifteen or
so domains are not.

## 2. The conventions, and why

**snake_case all the way through the live queries.** Table and column names stay
as Postgres spells them, through `useLiveQuery` and into the predicates. The
camelCase boundary is the query hook's output and `packages/domain` command
arguments. UI component props are camelCase and always were.

**One module per table, no barrel.** Each module calls `createCollection` at
import, which a bundler cannot treat as side-effect-free. A barrel re-exporting
54 of them is the same indivisible node under another name — which is what put
the entire collection graph in the boot chunk before (835 kB entry, verified by
building and grepping the chunks).

**The `Collection<Row, string | number>` annotation on every const is
load-bearing.** A `Collection<…>` instantiated inside `packages/sync` arrives in
`apps/web` as `any`, with no error anywhere. The type is written out in full in
the emitted `.d.ts` and every name in it resolves; copying that same text into
`apps/web/src` types correctly. It is specific to this app's
`moduleResolution: Bundler`. Ruled out: stale `dist`/`tsbuildinfo`,
project-reference source redirect, declaration maps, `skipLibCheck`, type size,
duplicate `@tanstack/db` instances, an explicit return type on the factory.

If an annotation is ever removed, the check is that `collection.id` (a `string`)
is refused where a `number` is wanted.

**One hook per file in `hooks/queries`, named for the hook.**
`useHabitatSearch` is `use-habitat-search.ts`. Files that are not `use-` files
are not hooks: `shared.ts`, and the per-domain view models.

## 3. What a query hook looks like

Read `apps/web/src/hooks/queries/shared.ts` first — it carries the rules.

**Surface hooks, not entity hooks.** A hook returns the shape one surface needs,
joined. An entity hook exists only where that entity is the page's subject (the
Habitat detail page, the Habitat typeahead).

**Transform in the query, with a compiled `select`.** Not a `.map()` in the hook
body, which re-runs on every render and hands out new objects. A compiled
`select` is part of the pipeline: it narrows what is materialized and a row whose
other columns moved produces no change downstream.

Exhaust the expression language before deciding it cannot say something —
`coalesce`, `caseWhen`, `concat`, `upper`, `lower`, `length`, the comparisons,
the arithmetic, the aggregates. `fn.select` takes arbitrary JavaScript and gives
up both properties; it also receives the *source namespaces* rather than a prior
projection, so a compiled `select` in front of it narrows nothing. Nothing in the
folder needs it.

A `useMemo` in a hook body is a sign the transform should have been a `select`.
The one exception is an index over the rows — a `Map` keyed by id — because a
query returns rows and cannot return a lookup of them.

**Join, do not waterfall.** Reading ids from one query and feeding them to a
second is a render round-trip and a second subset request. The join does it
inside the pipeline, and keeps up as rows arrive.

### Four traps, all of which cost real time to find

1. **`subsetMethod: 'POST'` is what makes joins work.** A join asks for one `IN`
   over every join key it matched; a couple of hundred uuids do not fit in a URL.
   On GET the request never lands, the joined side stays empty, the query never
   becomes ready — no error anywhere. Ten keys fit, so a small join works and a
   large one silently does not. It lives in
   `packages/sync/src/collections/functions/sync-collection.ts`.

2. **A `left` join yields `undefined`, not `null`,** and every `x.*` reference on
   an unmatched row is absent. Guard on the *driving* row's own column:
   `caseWhen(isNull(inspection.habitat_id), null, coalesce(...))`. Without it the
   fallback builds a label out of nothing and TypeScript reports the field as
   plain `string`.

3. **`coalesce` types better than `caseWhen(isNull(…), …)`** — the latter infers
   `string | null` because it cannot see the else branch is the column just
   tested.

4. **The "Join requires an index" warning is about the local snapshot pass, not
   the network.** It still appears with loading demonstrably correct. Every
   collection indexes `id` anyway (the local lookup seeks rather than scans), but
   do not treat the warning as a failure signal.

## 4. Browser verification

`.claude/launch.json` has `api` (3000), `web` (5173), `caddy` (5175, https). Use
`preview_start`; never Bash. The app is at `https://localhost:5175`.

- **The worktree needs `.env` and `apps/server/.env`**, copied from
  `F:\simmer-mosquito`. Worktrees do not carry gitignored files, and without them
  the API dies with `APP_ORIGIN must be set.` They are present now.
- **Sign-in is the user's job.** Entering a password is off-limits. Ask, then
  continue.
- **Probing collections from the console gives false readings.** Vite appends
  `?t=` to HMR-invalidated modules, so `import('/src/lib/collections/habitats.ts')`
  builds a *second* instance — it reads `size: 0, status: idle` while the page is
  visibly using the real one. To measure, temporarily publish the live modules:
  `(globalThis as any).__probe = { habitats, inspections }` inside the hook file,
  reload, read, remove.
- **Isolate before theorising.** The subset bug looked like two queries
  interfering; removing one panel from the page showed a single query loading
  zero rows, which pointed straight at the request. That test was worth more than
  an hour of reading library source.

## 5. The next moves, in order

1. **Migrate the remaining domains, surface by surface.** For each: write the
   joined hook(s) in `hooks/queries`, point the routes at them, drop that table
   from `createWebCollections` in `apps/web/src/sync/collections.ts`, and delete
   the domain's `*Mutations.ts` when its last table leaves. The compiler
   enumerates the consumers each time.

   Grep for the collection name to find consumers, **then follow the shared
   hooks out**. `webCollections.habitats` matched 12 files, but
   `useHabitatNames` in `-overview-data.ts` fed eight more pages across
   control-operations and operations. A definition site counts as one hit.

   Read existing shared hooks before replacing them — they carry undocumented
   bounds. `useHabitatNames` deduped ids and capped at 500; neither was visible
   from the call sites, and a dropped cap fails no test.

2. **Write hooks.** Reads stopped at the hook boundary but `mutateCollection`
   takes `changes` keyed by column, so forms still know table columns. Each
   domain's collections and its server intent map have to land together.

3. **`/map/*` and the explorers.** The habitat explorer's list rows come from
   `usePagedMapResource({ path: '/map/habitats' })`, not the collection — the
   server aliases every column to camelCase in `packages/db/src/domains`. Once
   collections are snake_case the two paths diverge and the same page holds both.
   Undecided: wrap the REST fetch in a hook returning the same view model
   (preferred), strip the aliases server-side, or leave it.

4. **Then the leftovers**: `packages/sync/src/rows/*`, the `fallow:health`
   baseline (run at the merge base with `main`, `6f5614e`, and diff before
   re-saving — a re-saved baseline can bury a regression), and
   `SIMMER_OPERATOR_ORG_ID` on Railway staging and production — without it every
   `/admin/*` call answers 403.

## 6. Casualties, all approved

- `getShapeServerUrl` / `VITE_SHAPE_SERVER_URL` — the factory takes one
  `serverUrl`. Both deployed environments left it unset.
- `sync-modes.ts` — each collection module states its own `syncMode` next to the
  collection it configures.
- `webBaselineCollectionKeys` / `preloadWebBaselineCollections` — already dead on
  `main`; nothing called them. If a boot warm-up is wanted it should be a real,
  called thing.
- A row of `collections` is an `AdultCollection`. Not a plural quirk —
  `Collection` is also what TanStack DB calls the thing that holds rows, so a
  module naming both cannot import them.
- Unnamed Habitats now label themselves with coordinates rather than
  `Habitat 3f2a1c9d`. **Open cosmetic issue**: the expression language has no
  `round`, so it renders full float precision, where `formatCoordinates`
  (`lib/coordinate-label.ts`) shows five places on ad-hoc rows. Both appear on the
  same page. The clean fix is rounding `lat`/`lng` where the trigger writes them.
